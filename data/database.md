# Database

PostgreSQL 17 managed by CloudNativePG. One instance in dev, three in prod.

## pgvector

The operand image is built from the CloudNativePG base with
`postgresql-17-pgvector` added, because stock CNPG images do not ship the
extension and it is a compiled module rather than something an init script
can create.

The extension is created by `postInitApplicationSQL`, not `postInitSQL`.
CNPG runs `postInitSQL` against the `postgres` database and
`postInitApplicationSQL` against the application database. Using the wrong
one creates the extension where the application never connects, and nothing
fails at provisioning time — it surfaces much later as
`type "vector" does not exist`, which looks like a broken image.

Initdb hooks do not re-run, so fixing this on an existing cluster means
creating the extension by hand or rebuilding.

## Connecting

CloudNativePG publishes three services: `jenie-pg-rw` for writes,
`jenie-pg-ro` for read-only replicas, and `jenie-pg-r` for any instance.
Credentials are generated by the operator and published as the
`jenie-pg-app` secret. Terraform does not create a database password —
two sources of truth for one secret is how they drift.

## Schema

One table, `chunks`, holding the document path, heading trail, content, a
384-dimension embedding, and a generated `tsvector`. There is an HNSW index
on the embedding for cosine distance and a GIN index on the tsvector.

Reindexing a document deletes its rows first, so shrinking a file does not
leave orphaned chunks behind.
